### #41 自チームの先攻・後攻を選べるようにする

`Game` に `isMyTeamHome: Bool = true` を追加。既定 true は、この項目が無かった頃の記録が
すべて自チーム＝後攻で保存されているため。

設計の要:
`homeScore` / `awayScore` / `InningScore.isHome` の「home/away」は **先攻・後攻の枠**という
意味を保ち、自チームかどうかは `isMyTeamHome` を掛け合わせて導く。これで既存データは無変換のまま動く。

- `Game.myTeamScore` / `Game.opponentScore` を追加（枠ではなく自チーム視点で読む）
- `AppStore.myTeamInningRuns(for:)` / `opponentInningRuns(for:)`
- `GameRecordResult.from(game:)` に変更（旧 `from(homeScore:awayScore:)` は自チーム=home 前提だった）
- `SeasonSummary` の勝敗・総得点を自チーム視点に
- `CreateGameView` に先攻／後攻セクション。**表・裏という記号ではなく実際のチーム名を並べる**
  （ユーザー要望「UI のわかりやすさにこだわって」。表裏だけだと自チームがどちらか読み取れず逆に記録される）
- イニング入力に列ヘッダー（表／裏 + チーム名）を追加、合計行もチーム名表示
- `GameDetailView` のラインスコアは先攻が上段。`isMyTeamHome` で上下が入れ替わる
- 詳細ヘッダーに先攻／後攻の chip を追加
- テスト `BattingOrderTests` 9件追加、全てパス

### #42 アプリの表示名を日本語で「草野球マッチ」に

`InfoPlist.xcstrings` を新規作成し `CFBundleDisplayName` をローカライズ（ja: 草野球マッチ / en: BaseMatch）。

**踏んだ罠**: ビルド設定の `INFOPLIST_KEY_CFBundleDisplayName` を残したまま xcstrings を置くと
`CFBundleDisplayName` が二重定義になり、**テストランナーがアプリを起動できなくなる**
（`FBSOpenApplicationErrorDomain Code=6 "Application failed preflight checks"`）。
ビルド設定側のキーを削除して解決。フォールバックは `CFBundleName` = BaseMatch。

下地の `groupedBackground`（明色）が覗いていた。`ScrollView` の背後に濃色を敷いて解決。

### #44 試合がずっと「記録中」のまま → 記録中の仕組みごと廃止

**原因**: `finalizeGame` を呼ぶ導線が UI に一つも無かった。`GameRepository.finalizeGame(id:)` と
`AppStore.finalizeGame(id:)` は実装済みでテストもあったが、どの画面からも呼ばれていない。

**判断**（ユーザー）: 確定ボタンを足すのではなく、記録中という状態自体を廃止する。
試合の作成・編集がいつでもできる以上、状態を分ける意味がない。

- `GameStatus` enum、`finalizeGame`（Repository / AppStore）、`AppStore.draftGames` を削除
- ホームの「記録中の試合」欄（`HomeDraftGameSection` / `DraftGameCard`）を撤去
- `GameRecordCard` の記録中バッジ分岐を削除し、常に勝敗を出す
- `GameDetailView` の「確定済みなら編集ボタンを隠す」分岐を削除
- L10n / xcstrings から `home.draft.*` を削除。未使用の `inningRunsAccessibility` も削除
- `Game.statusRaw` は **SwiftData の列として残す**（削除すると既存ストアの移行が要る）。既定値は `""`
- UI テスト `HomeTests` を「直近の試合カードから詳細へ入れる」検証に置き換え、
  `recentGameCard` の accessibilityIdentifier を追加

ユニットテスト・UI テストとも通過。
